# EXP-61h 干扰 token 探测直觉 — 结果记录

日期: 2026-08-11 | 用户设计 | 干预式探测方法论

## 实验

将 logical_and 拆成两个**同义 clone token**（D:9001/c0, D:9002/c1, 相同定义）,
训练时严格交替替换 and → c0/c1（完全等量 58/58）, 训练后观测单 clone 推理。

## 结果 (判定口径, run_exp 官方)

| 测试 | 判定 |
|---|---|
| 只用 c0 (logical_and_c0) | **1.000** |
| 只用 c1 (logical_and_c1) | **0.000** |
| 混合 c0/c1 | 0.250 (偏斜随机) |
| 训练内 (c0/c1 混合) | 0.845 |
| train acc | 0.980 |

## 核心发现

**结构集中 (canonical 化), 非直觉均匀分布。**

即使 c0/c1 **严格等量** (58/58) 训练, 模型仍:
- 完全学会 c0 (只用 c0 → 1.000)
- 完全忽略 c1 (只用 c1 → 0.000)

**"直觉均匀分布在同义 token 上"的假设被否定** — 编译后的直觉路径同样
canonical 化, 收敛到单一 token (c0), 不保留同义冗余。

**"结构尝试集中在一个 token 上"的假设被强支持** — 模型天然选一个
canonical token, 即便两 token 语义完全等同且训练等量。

## 解释

1. **Transformer 权重 canonical 化**: 同义 token 冗余在训练中被消除 —
   模型只需一个"and 位置"的权重向量, 第二个 token 的 embedding 被推走
   (未更新到有用方向), 所以 c1 位置输出错误。
2. **直觉 = 编译, 编译 = 消冗余**: 直觉路径 (权重) 天然压缩冗余 —
   与"直觉是编译结果"一致: 编译不保留可消除的重复。
3. **对用户框架的意义**: "用精确的逻辑构造获得直觉" — 构造 (逻辑) 是
   确定的, 直觉 (编译) 也继承确定性, 不保留歧义 token。同义 token 是
   语法冗余, 编译消除之。

## 局限

- 样本量 1000 (exp61g_infix 套件), 15 epochs — 小规模
- 单 op (logical_and) — 未推广到多 op 混合
- 注意力权重未直接观测 (间接: 单 token 推理), 未来可用 attention map

## 后续 (用户建议方向)

- 拆 N 个 token (3/4) 看 canonical 化是否仍单点
- 干扰强度扫描 (拆越多语法越乱)
- 反向: 若想保留均匀分布, 需什么训练条件 (强制对称? 同时监督两 clone?)

## 变体矩阵 (用户要求: 拆 N token 扫描)

| 变体 | token 组合 | c0 | c1 | c2 | 解读 |
|---|---|---|---|---|---|
| V2same | and/and | **1.000** | 0.000 | — | canonical 化 (集中 c0) |
| V3same | and/and/and | 0.000 | 0.000 | **0.750** | 集中 c2 但不完整 |
| V2diff | and/or | **1.000** | 0.000 | — | 集中 and, or 被忽略 |
| V3diff | and/or/xor | 0.000 | 0.000 | 0.250 | 崩 (语义无法归因) |
| V3mix | and/and/or | 0.000 | 0.000 | 0.250 | 崩 (and 分散无法归因) |

## 变体结论

1. **2 token 时结构强集中** (V2same/V2diff): 模型收敛到单一 canonical token,
   另一 token (即使不同语义 or) 完全被忽略 — "结构尝试集中在一个"强支持。
2. **≥3 token 时崩** (V3same 0.75 / V3diff 0.25 / V3mix 0.25):
   "拆得越多语法越乱" — 多个同位置 token 使模型无法归因语义,
   同义冗余 (V3same) 尚可部分集中 (0.75), 语义混合 (V3diff/V3mix) 彻底崩。
3. **直觉均匀分布假设被否定**: 编译路径不保留同义冗余 (2 token 时),
   且语义冗余不被容忍 (V2diff 的 or 被丢)。
4. **归因能力边界**: 模型在同一"op 位置"能处理 ≤2 个候选 token;
   ≥3 个时退化 (注意力无法在位置语义间归因) — 这量化了语法的
   "位置-候选"容量。

## 理论意义: 位置敏感性与直觉/逻辑的分化 (用户洞察 2026-08-11)

**用户的日常现象观察**: 把一句话的符号打乱 (字母乱序) 不影响理解 — 
直觉天然适应混乱的快路径, **位置不敏感**; 而一旦集中精神仔细激活逻辑时,
这段话就失去含义 — **逻辑需要确定位置**。

**本实验的连接 (EXP-61h)**:
- **结构集中 (canonical, 位置确定)**: 2 个同义 token 时模型收敛到单一
  canonical token (V2same: c0=1.0 c1=0.0) — 逻辑路径要求"op 在确定位置",
  冗余 token 被消除。
- **直觉位置不敏感 (推测)**: 符号打乱仍可理解 = 直觉快路径不依赖精确
  位置 (对 token 排列鲁棒) — 对应 EXP-80 的 100% 匿名置换仍 1.000
  (快路径对符号/位置混乱鲁棒)。
- **逻辑位置敏感**: V3diff/V3mix 崩 (≥3 候选无法归因) = 逻辑路径需要
  明确位置-语义映射, 位置歧义导致失去含义。

**统一框架解释**:
- 直觉 (快路径, 编译): 位置不敏感, 容忍 token 排列混乱 — 因为编译
  提取了结构关系 (哪两个数相加), 不依赖符号呈现顺序。
- 逻辑 (慢路径, 构造): 位置敏感, 需要确定位置-语义映射 — 因为构造
  是定义驱动的确定性展开。
- "符号打乱不影响理解" = 理解发生在直觉通道 (位置不敏感);
  "集中逻辑时失去含义" = 激活逻辑通道时位置歧义暴露。

**这为 G5 (直觉/推理分离) 提供认知机制**: 直觉 = 位置不敏感的编译快路径;
逻辑 = 位置敏感的构造慢路径。两路径对 token 位置/符号混乱的鲁棒性不同。
